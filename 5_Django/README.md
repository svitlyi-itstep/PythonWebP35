## 1. Що таке веб-фреймворк?

Коли розробник пише веб-застосунок «з нуля», йому доводиться самостійно вирішувати десятки однотипних задач: як прийняти HTTP-запит, як розібрати URL, як з'єднатися з базою даних, як захистити форму від підробки, як відрендерити HTML. Ці задачі однакові в будь-якому застосунку — незалежно від предметної області.

> **Веб-фреймворк** — це готова бібліотека (або набір бібліотек), яка вирішує всі ці типові задачі за розробника. Замість того щоб писати обробку HTTP вручну, розробник описує лише бізнес-логіку, а фреймворк бере на себе все інше.

## Ключові можливості Django

### ORM (Object-Relational Mapping)

Django дозволяє працювати з базою даних через Python-класи, не пишучи SQL вручну.

```python
# Замість SQL: SELECT * FROM books WHERE year > 2000
books = Book.objects.filter(year__gt=2000)

# Замість SQL: INSERT INTO books ...
Book.objects.create(title="Dune", author="Herbert", year=1965)
```

Підтримуються: SQLite, PostgreSQL, MySQL, Oracle.

### Автоматична адмін-панель

Django генерує повноцінний інтерфейс адміністратора автоматично — достатньо зареєструвати модель:

```python
# admin.py
from django.contrib import admin
from .models import Book

admin.site.register(Book)
```

Після цього за адресою `/admin/` доступний готовий CRUD-інтерфейс із пошуком, фільтрами та пагінацією.

### Система маршрутизації

```python
# urls.py
from django.urls import path
from . import views

urlpatterns = [
    path("books/",        views.book_list,   name="book-list"),
    path("books/<int:pk>/", views.book_detail, name="book-detail"),
]
```

### Вбудована безпека

Django за замовчуванням захищає від найпоширеніших веб-атак:

| Загроза | Захист Django |
|---|---|
| SQL-ін'єкція | ORM екранує всі запити |
| XSS | Шаблонізатор екранує HTML автоматично |
| CSRF | Токен у кожній формі |
| Clickjacking | Заголовок `X-Frame-Options` |

### Шаблонізатор (Django Templates)

```html
{% for book in books %}
  <p>{{ book.title }} — {{ book.author }}</p>
{% endfor %}
```

### Система міграцій

Зміни в моделях автоматично перетворюються на SQL-скрипти і застосовуються до бази:

```bash
python manage.py makemigrations
python manage.py migrate
```

## Архітектура: патерн MVT

Django реалізує власний варіант MVC — **MVT (Model – View – Template)**:

![alt text](https://codefinity-content-media.s3.eu-west-1.amazonaws.com/f9161f23-e81e-4082-9642-0a0c970c68aa/899e5b82-04d9-4bb5-b3a8-e18ae1cf90b8_MVT.png)
<sup><sup>Джерело: https://codefinity.com/courses/v2/f9161f23-e81e-4082-9642-0a0c970c68aa/0ce97d0f-ac61-4db5-9ea5-9590e9c7f14c/899e5b82-04d9-4bb5-b3a8-e18ae1cf90b8</sup></sup>

| Шар | Файл | Відповідає за |
|---|---|---|
| Model | `models.py` | Структура даних, запити до БД |
| View | `views.py` | Логіка обробки запиту |
| Template | `templates/*.html` | Відображення (HTML) |
| Router | `urls.py` | Який URL → яка View |

### Django

```
Філософія: «Все вже є — просто використовуй»
```

**Переваги:**
- повний набір інструментів «з коробки»: ORM, адмін, автентифікація, форми, міграції
- дуже велика спільнота і екосистема пакетів
- чудова документація
- чіткі конвенції — менше рішень «як організувати код»

**Недоліки:**
- «надмірно важкий» для простих API або мікросервісів
- менша гнучкість порівняно з мікрофреймворками
- асинхронна підтримка з'явилася пізніше і досі не охоплює всі компоненти

**Коли підходить:** великі веб-застосунки, CMS, платформи з адмін-панеллю, командні проєкти.

---

### Flask

```
Філософія: «Мінімум обмежень — максимум свободи»
```

Flask — мікрофреймворк: надає лише роутинг і обробку запитів. Усе інше (ORM, автентифікацію, міграції) розробник підключає окремими бібліотеками на власний розсуд.

```python
from flask import Flask
app = Flask(__name__)

@app.route("/")
def index():
    return "Hello, World!"
```

**Переваги:**
- простий старт, мінімум «магії»
- повний контроль над архітектурою
- ідеальний для навчання принципам HTTP

**Недоліки:**
- для великих проєктів треба самостійно збирати стек
- немає єдиних конвенцій — команди часто вигадують структуру самі

**Коли підходить:** прості REST API, прототипи, навчальні проєкти, мікросервіси.

---

### FastAPI

```
Філософія: «Швидко, сучасно, з документацією безкоштовно»
```

FastAPI — сучасний асинхронний фреймворк для побудови API. Використовує Python-анотації типів для автоматичної валідації даних і генерації Swagger-документації.

```python
from fastapi import FastAPI
app = FastAPI()

@app.get("/books/{book_id}")
async def get_book(book_id: int):
    return {"id": book_id, "title": "Dune"}
```

**Переваги:**
- автоматична генерація документації (`/docs`)
- висока продуктивність (порівнянна з Node.js)
- строга типізація через `pydantic` — менше помилок

**Недоліки:**
- не має ORM та адмін-панелі «з коробки»
- молодша екосистема, менша спільнота

**Коли підходить:** RESTful та GraphQL API, мікросервіси, проєкти де важлива продуктивність.

---

### Tornado

```
Філософія: «Мережеві застосунки реального часу»
```

Tornado — асинхронний мережевий фреймворк, розроблений у FriendFeed (придбаний Facebook). Орієнтований на підтримку тисяч одночасних з'єднань: WebSocket, long polling, чати.

```python
import tornado.web, tornado.ioloop

class MainHandler(tornado.web.RequestHandler):
    def get(self):
        self.write("Hello from Tornado")

app = tornado.web.Application([(r"/", MainHandler)])
app.listen(8888)
tornado.ioloop.IOLoop.current().start()
```

**Переваги:**
- відмінна підтримка WebSocket і довготривалих з'єднань
- дуже висока продуктивність при великій кількості підключень

**Недоліки:**
- нестандартний підхід, крута крива навчання
- мала спільнота, мало сторонніх пакетів

**Коли підходить:** чати, ігрові сервери, застосунки реального часу, стримінг.

---

### Pyramid

```
Філософія: «Починай малим, ростемо разом з проєктом»
```

Pyramid — гнучкий фреймворк, що займає нішу між Flask (мікро) і Django (full-stack). Не нав'язує ORM чи шаблонізатор, але має розвинуту систему конфігурації та авторизації.

```python
from pyramid.config import Configurator
from pyramid.response import Response

def hello(request):
    return Response("Hello from Pyramid")

with Configurator() as config:
    config.add_route("hello", "/")
    config.add_view(hello, route_name="hello")
    app = config.make_wsgi_app()
```

**Переваги:**
- гнучкий, не нав'язує рішень
- добре масштабується від малих до великих проєктів
- розвинена система ACL-авторизації

**Недоліки:**
- невелика спільнота
- для старту потрібно більше конфігурації

**Коли підходить:** проєкти з нестандартними вимогами до авторизації або архітектури, enterprise.

### Загальна рекомендація для вибору

```
Потрібен повноцінний сайт / платформа?     → Django
Простий REST API або прототип?             → Flask
Сучасний API з документацією і типізацією? → FastAPI
Реальний час / WebSocket / чат?            → Tornado
Нестандартна архітектура / ACL?            → Pyramid
```
